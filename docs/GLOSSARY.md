# Glossary

- **AICTE:** All India Council for Technical Education; the target regulatory context for the project, not a claim that this prototype is an official AICTE product.
- **Application snapshot:** Immutable view of the application fields and evidence versions evaluated by a validation run.
- **Authorized source:** A record/service the project is permitted to query and for which access and provenance are known.
- **BHASHINI:** Government of India language technology ecosystem; actual API access, service support, terms, quotas and credentials must be checked.
- **Digital twin:** A time-aware, provenance-attributed model of the institution assembled from submitted, extracted, reviewed and authorized-source facts. Not an official registry by default.
- **Evidence graph:** Typed relationships linking applications, evidence versions, extracted fields, rules, findings, source responses and review actions.
- **Exact duplicate:** File bytes yield the same cryptographic hash. This says nothing about issuer authenticity.
- **Finding:** An explainable observation or rule result that needs no inference beyond its disclosed evidence; may require human review.
- **Issuer verification:** Query to a supported, authorized issuing source; a local/synthetic fixture is not issuer verification.
- **Near duplicate:** Similarity candidate generated by a documented algorithm/threshold; always a review lead.
- **OCR:** Optical character recognition, which transforms image text into machine-readable text and can make errors.
- **P0/P1/P2:** Mandatory base scope / additive prototype scope / later enhancement.
- **RAG:** Retrieval-augmented generation; the copilot retrieves approved source passages then drafts a response grounded in citations.
- **Rule pack:** Versioned collection of deterministic declarative checks for application category/year/effective period.
- **Source anchor:** Page, bounding box, paragraph/field path or file version that supports a finding.
- **Synthetic fixture:** Invented test/demo data, labelled as fictional and not presented as official records.
- **Tenant scope:** Institution/case boundaries that restrict who can view or mutate data.
- **Validation run:** Immutable set of rule and signal results pinned to input snapshot, rule versions and engine versions.
